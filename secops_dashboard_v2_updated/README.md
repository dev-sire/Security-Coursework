# Windows Security Dashboard — Detection Engineering Project

## What's real vs. mocked (read this first)

| Component | Status | Notes |
|---|---|---|
| Sandbox ransomware **behavior** simulation | **Real, benign** | No encryption/propagation. Reproduces the T1486/T1490 telemetry pattern only (mass rename, ransom note, logged-but-not-executed vssadmin call). |
| Local detection rules | **Real logic** | Genuine threshold/pattern matching over telemetry JSON. |
| ML training | **Mocked** | No labeled dataset was available. Prints realistic epoch/accuracy progress and saves `model_metrics.json`, clearly flagged `MOCK_TRAINED`. |
| ML inference | **Real feature extraction, mock model weights** | Features (rename rate, note presence, shadow-copy attempt) are genuinely extracted from telemetry; scored with a deterministic weighted heuristic standing in for a trained classifier. |
| LLM opinion | **Real Gemini call if `GEMINI_API_KEY` is set** | Falls back to a clearly labeled mock pipeline (`[LLM][MOCK] Ollama is processing...`) if no key / no local runtime is present, as requested — this is cosmetic log text only, it does not claim a model actually ran. |
| Firewall / FADE dataset | **Mocked** | No canonical "FADE" dataset file was provided. A synthetic flow dataset is generated using a FADE-style schema (5-tuple + flow stats). Firewall rule logic itself is real. |
| CVE/CWE/NIST/PCI/PECA mapping | **Real reference IDs** | `compliance/mapping.json` uses genuine published CWE/NIST 800-53/PCI DSS v4 control numbers and real historical CVEs cited for context. PECA 2016 is a legal statute, mapped at the section level, not a technical control — noted explicitly in the file. |

**No ransomware encryption code exists anywhere in this project.** I won't build that even in a sandbox — see the note in `sandbox/simulate_ransomware_behavior.py` for why the behavioral-simulation approach (same one MITRE Atomic Red Team uses) is actually the more defensible engineering choice for a detection demo.

## Live Windows telemetry (new, real data)

| Component | Status |
|---|---|
| `telemetry/windows_collector.py` | **Real, read-only.** Processes, scheduled tasks, TCP connections, shadow copies, Run keys, Defender status, ransomware-style filenames (names/metadata only, contents never read). Windows only. |
| `detection/windows_rules.py` | **Real heuristics** over the snapshot (WIN-001..012, mapped to ATT&CK/NIST/PCI). Findings are triage leads, not verdicts; each shows its evidence row. |
| `telemetry/samples/FIXTURE_not_real_snapshot.json` | **Hand-written test fixture**, labeled `hand_written_fixture`. Not host data. Do not present it as real. |

Usage: run `python server.py` on the Windows machine (elevated shell for fuller results), open **Live Windows**, click **Collect Now**.
No Windows server? Run `python telemetry/windows_collector.py --out snap.json` on the Windows host, then **Analyze snapshot JSON**.
`server.py` now binds to 127.0.0.1 by default (`python server.py 8000 0.0.0.0` to expose it; don't, the endpoints return host telemetry) and no longer sends `Access-Control-Allow-Origin: *`.

## How to run

```bash
cd secops_dashboard
pip install --upgrade pip   # no extra deps required - stdlib only

# Optional: use real Gemini instead of the mock LLM fallback
export GEMINI_API_KEY="your-key-here"

python3 run_pipeline.py
```

This will:
1. Run the benign ransomware-behavior simulation in `sandbox/`
2. Evaluate local detection rules
3. Run the mock ML training + inference
4. Call Gemini (or fall back to the mock local-LLM log output)
5. Generate the synthetic FADE flow dataset and evaluate firewall rules
6. Write `dashboard/feed.json`

## How to view the dashboard (live mode)

Use `server.py` from the project root, not `http.server` — it's what powers
the "Run Live Detection" button and the in-dashboard API key field:

```bash
cd secops_dashboard
python3 server.py 8000
```

Then open `http://localhost:8000`. Click **Run Live Detection** at any time —
it re-runs the entire pipeline (sandbox simulation → rules → ML → LLM →
firewall) on the server and pushes the fresh result straight into the
dashboard, no manual refresh or terminal re-run needed.

To use real Gemini instead of the built-in simulated LLM pipeline, click
**⚙ AI API Settings** and paste your key — it's written to `config.json` on
the server and used on the next live run. (You can also still set
`GEMINI_API_KEY` as an environment variable before starting `server.py`;
either way works, `config.json` takes precedence if both are set.)

### Standalone ransomware behavior test

`sandbox/test_ransomware.py` is a standalone, double-clickable version of the
same benign simulation (`python3 sandbox/test_ransomware.py`) — useful if you
want to generate telemetry on its own without running the full pipeline, then
hit "Run Live Detection" in the dashboard to have it analyzed.

### If you just want the old static mode

`python3 -m http.server 8000` from inside `dashboard/` still works for
viewing a pre-generated `feed.json`, but the Run Live Detection button and
API key field won't work without `server.py`.

## Re-running after changes

Just re-run `python3 run_pipeline.py` from the project root — it regenerates
`telemetry.log`, `model_metrics.json`, `fade_flows_mock.csv`, and `feed.json`
each time, so the dashboard always reflects the latest run.

## Where you'd plug in real data later

- Swap `ml_classifier.mock_train()` for a real scikit-learn/XGBoost fit on
  labeled Windows event data (Sysmon/Wazuh exports).
- Swap `firewall/generate_fade_dataset.py` for a loader of your actual FADE
  source file, keeping the same column schema.
- `llm_opinion.py` already calls real Gemini when `GEMINI_API_KEY` is set —
  no code change needed, just set the env var.
- Extend `compliance/mapping.json` with additional ATT&CK techniques as you
  add rules.
